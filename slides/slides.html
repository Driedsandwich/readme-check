The problem

README install steps rot.
The first to find out is whoever runs them.

You follow a repo's install instructions and something breaks. Is it your machine, or is the README out of date?

  1. More and more often, the one running the README is an AI coding agent on someone's laptop.
  2. It reads the README, runs the commands, fails —
  3. then gives up silently, or “fixes” things on your laptop.
Real example · openai/baselines

The README (last commit 2020-01-31) asks for

pip install tensorflow==1.14

TensorFlow 1.14 was only published for Python 2.7–3.7. The README was correct for 2019, but not in today's default sandbox (Python 3.14).

Sponsor products, used deeply

Daytona runs the README. Nosana explains the break.

Daytona

  • A throwaway Linux machine per check: daytona create --auto-delete 0 --ttl 30
  • Up in seconds: the daytona create call returned in 3.3 s and 3.8 s (wall-clock, today's two saved runs)
  • Git, pip and passwordless sudo inside
  • Real exit codes from daytona exec --timeout
  • Clone, install and fail there — no install step runs on the user's or the agent's host; delete at the end

Nosana

  • The explanation model runs on a Nosana GPU deployment (decentralised GPU marketplace)
  • Ollama qwen2.5:3b on an RTX 3060-class GPU, OpenAI-compatible API
  • Turns the failing step into a one-line human reason — verified today on an RTX 3060-class GPU deployment (redeployed with a writable model store)
  • Nosana deployment answered today; reason_by in result.json records it
  • If Nosana is unreachable, falls back to the raw error line

Why it matters · what's next

Know a README is broken before anyone (or any agent) trips on it

Why it matters

  • Maintainers: stale-README detection — the exact line, the exact error, the environment it ran in.
  • AI agents: safer onboarding — check in a throwaway sandbox instead of trying it on someone's laptop.
  • Everyone: tell “the README is stale” from “my environment is odd”.

Next (plans)

  • Suggest a README patch, then re-verify it in a new sandbox.
  • Check many repos at once in parallel sandboxes.

Honest limits today: only fenced shell blocks are read; interactive prompts, GUI steps and steps needing API keys are not handled; only the first failing step is reported; extraction is rule-based (repeatable runs).
